01 / The Problem

Tanzania Has a Water Access Crisis

Tanzania is home to more than 67 million people, and access to clean water remains one of the country's most pressing public health challenges. Across the country, tens of thousands of wells provide water for drinking, cooking, and sanitation, but a significant portion are broken or failing.

Testing every well individually is expensive and slow. Field organizations need a smarter way to triage: which wells should they visit first? This project builds a classification model to answer that question, using well characteristics available in existing records to predict which ones need repair.

The cost of getting it wrong is not symmetrical. Missing a broken well (a false negative) means a community goes without clean water. That asymmetry shapes every modeling decision in this project, starting with the choice of evaluation metric.

02 / The Data

59,400 Wells, 41 Features

The dataset comes from Taarifa and the Tanzanian Ministry of Water, collected as part of the DrivenData Pump It Up competition. Each row represents one well, with information about its location, water source, installer, construction year, management structure, and current status.

The target variable, status_group, originally has three classes: functional, functional needs repair, and non-functional. For this project, the three classes were collapsed into a binary target: needs repair vs. does not need repair. This simplification focuses the model on the decision that actually matters in the field.

After cleaning (dropping redundant features, handling nulls, and reducing cardinality on high-dimensionality columns like installer), the dataset was trimmed to 19 features and roughly 47,000 records.

  • Wells installed by government entities and certain foreign contractors show higher non-functional rates
  • The Ruvuma/Southern Coast and Lake Rukwa basins have disproportionately high failure rates
  • Numeric features like population and GPS height are right-skewed, so MinMaxScaler was applied during preprocessing
  • The installer column had 2,145 unique values, reduced to 26 categories by grouping low-frequency entries

04 / The Model

Why Recall, and Which Model Won

Standard accuracy is a poor metric here. A model that predicted every well as functional would still hit roughly 54% accuracy — without ever flagging a single well for repair. The metric that matters is recall: out of all the wells that actually need repair, what share did the model catch?

Four model types were trained and compared: logistic regression as a baseline, then decision tree and random forest classifiers with progressively more tuning. Feature selection via recursive feature elimination and hyperparameter tuning via GridSearchCV were applied to reduce overfitting.

Model Recall False Negative Rate Overfit Gap
Baseline Logistic Regression 71.2% 28.8% Low
Decision Tree (tuned) 68.4% 31.6% Moderate
Random Forest (initial) 77.8% 9.7% High
Random Forest (tuned) 72.1% 27.9% Moderate

The initial random forest achieved the best recall and the lowest false negative rate, despite showing signs of overfitting. A missed well means a community loses water access, so the false negative rate took priority over generalization. The tuned models reduced overfitting but at a meaningful cost to recall.

05 / Recommendations

Where to Focus and What to Do Next

  • 1

    Start in Kigoma and the Southeast

    The spatial analysis points to Kigoma in the northwest and Mtwara and Lindi in the southeast as the highest-need areas. These regions combine high well failure rates, large populations, and limited access to nearby functional wells. Field teams should prioritize these for the first wave of inspections.

  • 2

    Deploy the initial random forest for triage

    Despite overfitting on training data, the initial random forest keeps the false negative rate at 9.7%, the lowest of any model tested. Deploying it now provides a practical starting point for prioritizing well visits while refinements continue in parallel.

  • 3

    Invest in better data collection

    Several potentially useful features — installer, scheme management, and construction year had significant data quality issues. More accurate and complete records would improve model performance and reduce the need for heavy preprocessing decisions that may be losing signal.

06 / Next Steps

Where This Project Goes From Here

  • Explore gradient boosting methods (XGBoost, LightGBM) which may better balance recall and generalization than random forests
  • Run broader hyperparameter searches with more compute — the GridSearchCV grids were constrained by time and memory
  • Incorporate spatial features directly into the model — distance to nearest functional well and regional repair rate as engineered predictors
  • Partner with local agencies to validate predictions against ground-truth well inspections and refine the model with updated data
